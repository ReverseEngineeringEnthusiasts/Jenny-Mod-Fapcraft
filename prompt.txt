2. THE TOOLING — HOW EVERYTHING WORKS
=====================================================================
---- 2a. MCP mappings (the CSV source of truth) ----
  tools/mappings/{methods,fields,params}.csv  (MCP stable_39 for MC 1.12; func_XXX,name,side,comment)
  Source: official MCP via wayback snapshot of files.minecraftforge.net
    (mcp_stable-39-1.12.zip). Keep these in the repo; do not lose them.
  NOTE: the CSV has SIDE-specific entries (side 0=client, 1=server, 2=both). Two funcs can share one
  MCP name+desc (e.g. func_70071_h_=onUpdate=both AND func_189213_a=onUpdate=client). MCRepack
  resolves these by preferring side-2 ("both"). See betterSide().

---- 2b. MCRepack (the remapper, lives in tools/) ----
  java -cp "tools:lib-repo/local/asm/7.1/asm-7.1.jar:.../asm-commons-7.1.jar:.../asm-tree-7.1.jar" \
      MCRepack <srgJar> <methods.csv> <fields.csv> <mode> <in.jar> <out.jar>
  mode:
    srg2mcp  -> rename func_XXX/field_XXX to MCP names (generates mc-1.12.2-mcp.jar etc.)
    mcp2srg  -> rename MCP names back to SRG (reobfuscates the built mod jar)
  It scans the SRG jar for (name, desc) of every func_XXX/field_XXX, builds a (name,desc) -> mapped
  map, and applies with ASM ClassRemapper. It uses (name, desc) matching so mod methods that merely
  share an MCP name with MC (e.g. getCurrentAction) are NOT wrongly renamed, while genuine MC
  overrides (onUpdate, doRender, getEntityTexture...) ARE renamed to their SRG names.
  Field reobfuscation is scoped to net/minecraft/* owners.
  Regenerate MCP jars (e.g. after changing mappings): tools/regenerate-mcp-jar.sh
  TinyGen.java in tools/ generates a Tiny v2 mapping from the same CSVs (used if you ever want
  to try tiny-remapper / Fabric-style tooling).

---- 2c. Build / reobfuscation flow ----
  pom.xml:
    - compile deps: local:mc-1.12.2-mcp, local:geckolib3-1.12.2-mcp, forge, ASM (provided)
    - maven-shade-plugin packages geckolib + shadowed libs
    - maven-antrun-plugin (reobf-srg, phase=package) runs MCRepack mcp2srg in-place on the shaded jar
  Order matters: shade MUST run before antrun. Output = target/fapcraft-1.12.2-1.1.0.jar (SRG).
  Deploy: copy that jar into the Prism instance mods folder
  (only ONE fap jar active at a time; same modid).

---- 2d. Verification against the original ----
  Original jar: Fapcraft.1.12.2.v1.1.jar. Ground truth = its BYTECODE (SRG names).
  - javap -c -p -classpath lib/mc-1.12.2-srg.jar <net.minecraft class>  -> check a vanilla method's SRG name
  - javap -c -p -classpath target/fapcraft-1.12.2-1.1.0.jar <mod class> -> confirm SRG names in final jar
  - To check the original mod's classes: extract the jar and javap the obfuscated classes
    (e.g. em = BaseGirlEntity, eb = LunaEntity, s$a = ResetGirlPacket.Handler, d_ = GirlRenderer).
  - Decompiler tools available in the Zyvori dev-kit (cfr/fernflower/vineflower/procyon/jadx/krak2)
    and Recaf MCP (headless recaf + 28 MCP tools) for heavy lifting.

---- 2e. Recaf MCP ----

4. RULES / PITFALLS (things that broke before — avoid)
=====================================================================
1. NEVER guess a rename. If you can't determine a method's purpose, leave it obfuscated and note it.
   Wrong names are worse than obfuscated names.
2. Do NOT rename the mod's OWN methods to MCP names that collide with vanilla MCP names
   (e.g. don't create a method named `getModel` unless it truly is one). The reobfuscator uses
   (name, desc); an exact (name, desc) collision WILL be reobfuscated and break the mod.
3. Do NOT remove or change override names on geckolib/MC methods without verifying javac generates
   the right bridges. The dropped-bridge bugs (setLivingAnimations, render(GeoModel,Object),
   func_76986_a, func_77041_b) silently killed features — always rebuild and check bytecode.
4. Do NOT re-add "safety" resets to l_clash514/tickFollowUpTransitions or flip ResetGirlPacket
   booleans — both are jar-faithful now.
5. ALWAYS run `mvn clean package` after changes and confirm BUILD SUCCESS + the jar still has SRG
   names (spot-check: javap a class, expect func_XXX not getMinecraft).
6. Keep tools/mappings/*.csv and tools/MCRepack* in the repo; never edit the mappings by hand
   unless you truly know the MCP rename is wrong.
7. Commit often with the git-identity skill (repo-local RealCrystalNight config).
8. The MCP jar + geckolib-mcp jar are GENERATED. If you change the mappings, regenerate them
   with tools/regenerate-mcp-jar.sh and re-verify the build + final jar bytecode.
9. When in doubt about a vanilla method's MCP or SRG name: grep tools/mappings/methods.csv
   (func_XXX -> MCP) or javap lib/mc-1.12.2-srg.jar (the SRG name is the runtime truth).
